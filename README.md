# SQLite 事务隔离实验室

一个用于观察 SQLite（WAL 模式）事务隔离与写锁冲突行为的网页实验台。

- 后端：Python + Flask（直接调用标准库 `sqlite3`，真实执行 SQL）
- 前端：原生 HTML / CSS / JavaScript，无任何框架
- 每次「新建实验」都会得到一个独立的 WAL 数据库，内含单行整数值 `100`
- 页面左右两栏（甲 / 乙）各自绑定一条**长期独立连接**，可执行
  `BEGIN DEFERRED`、读值、加上输入整数、提交、回滚
- 第三条连接单独显示**已提交值**
- 状态刷新不执行任何 `SELECT`，不会为 DEFERRED 事务提前建立读快照
- 写锁冲突立即返回 SQLite 错误名与错误码（`busy_timeout=0`），
  不阻塞另一栏，也不会自动结束失败的事务
- 修改操作（加上）只允许在事务内进行，禁止事务外修改
- 实验仅保存在内存中，无需跨重启保留

## 数值约定

- 数据库中的值始终是**有符号 64 位整数**（`-9223372036854775808` ~
  `9223372036854775807`）。任何累加结果一旦越界，本次「加上」会被**拒绝且不执行**，
  事务保持开启，仍可继续提交或回滚；正、负边界本身都合法，绝不转成浮点数
  （避免 SQLite 整数溢出后静默变成 `REAL`）。该保证由表约束
  `CHECK(typeof(val) = 'integer')` 在 UPDATE 时原子强制：整数加法溢出产生的
  `REAL` 在列亲和性转换前即被拒绝（`SQLITE_CONSTRAINT_CHECK`）。
- 单次增量的绝对值上限仍为 `2^62`（`4611686018427387904`），超限返回
  `400 value too large`。
- **大整数一律以十进制字符串传输**：超出 JavaScript 安全整数范围
  （`Number.MAX_SAFE_INTEGER`，即 `9007199254740991`）的整数，在操作响应、
  状态轮询的 `last_read`、已提交值 `committed` 中均以 JSON 字符串形式返回，
  前端按文本显示，全程无损；日志文本中也始终使用十进制写法。
- 安全整数范围内的值仍返回 JSON **数字**；旧客户端直接以 JSON 数字发送小整数
  （如 `{"value": 10}`）的请求继续可用，服务端同时接受数字与十进制字符串。
- 适用范围：加法输入值、操作响应（`state.last_read`）、状态轮询
  （`/status` 中的 `last_read`）、最近一次显式读值、日志文本、已提交值
  （`/committed`）均为无损传输与存储。

## 操作示例

### 示例一：快照隔离与快照冲突（SQLITE_BUSY_SNAPSHOT）

1. 甲：`BEGIN DEFERRED` → `读值` → 显示 **100**
2. 乙：`BEGIN DEFERRED` → 输入 `10` → `加上` → `提交`
   （顶部「已提交值」变为 **110**）
3. 甲：`读值` → 仍为 **100**（甲的读快照不受乙已提交的修改影响）
4. 甲：`加上` → 立即报错 **SQLITE_BUSY_SNAPSHOT（错误码 517）**，甲的事务仍然开启
5. 甲：`回滚` → `BEGIN DEFERRED` → `读值` → 显示 **110**

### 示例二：写锁冲突（SQLITE_BUSY）

1. 甲：`BEGIN DEFERRED` → 输入 `5` → `加上`（先不提交，甲持有写锁）
2. 乙：`BEGIN DEFERRED` → `加上` → 立即报错 **SQLITE_BUSY（错误码 5）**，
   乙的事务不会被自动结束
3. 甲：`回滚`（释放写锁）
4. 乙：再次 `加上` → 成功 → `提交`（顶部「已提交值」随之更新）

### 示例三：超过 JS 安全整数的加法（精度无损）

1. 甲：`BEGIN DEFERRED`
2. 输入 `9007199254740993`（即 `2^53 + 1`）→ `加上` → 成功（尚未提交）
3. `读值` → 最近一次显式读值与日志均显示 **9007199254741093**（`100 + 9007199254740993`）
4. `提交` → 顶部「已提交值」显示 **9007199254741093**，而不是因
   `Number.parseInt` 丢精度得到的 90071992547410**92**

### 示例四：累加越过 64 位整数上界（拒绝越界加法，事务保持开启）

1. 甲：`BEGIN DEFERRED`
2. 输入 `4000000000000000000` → `加上`，连续两次均成功（尚未提交）
3. 第三次输入 `4000000000000000000` → `加上` → **拒绝**：累加结果
   超出有符号 64 位整数范围（`-9223372036854775808` ~
   `9223372036854775807`），本次加法未执行，事务仍保持开启；
   数据库中仍是整数而不是 `REAL`
4. 甲的事务保持开启：`读值` 显示前两次的结果 **8000000000000000100**
5. 此时仍可二选一：`提交`（已提交值变为 **8000000000000000100**）
   或 `回滚`（已提交值恢复为 **100**）

> 提示：一栏的请求未完成时，该栏按钮会被禁用，另一栏仍可正常操作；
> 两栏的状态轮询与「已提交值」均通过独立连接 / 内存状态完成，
> 不会干扰甲、乙两栏各自的事务快照。
